# 画像から教材図を作る

Mode A・B の手順の正本。種類の決め方と規約の要点は SKILL.md にある。

元画像を保存し、図の周囲にある式・説明も読む。切り出した範囲、図の向き、読める文字、印や矢印の数と位置を控える。筆圧の変化、板書のかすれ、罫線と筆記の関係から手描きと分かれば Mode A、活字・規則的な線・既存の清書図なら Mode B を選ぶ。汚れや撮影の傾きだけで印刷図を手描き扱いしない。判断がつかなければ該当箇所を示して確認する。

## Mode A　意図を読み取り、構造から作図する

手書きはデフォルメされた図である。線の揺れ・傾き・比率の崩れ・重ね書きは筆者の意図ではない。**この図は結局何を伝えたいのか**を考え、構造を理解してから描く。筆跡の位置をなぞらない。

### 1. 読み取って意図仕様を書く（描く前に）

図の周囲の式・説明も読み、`<図>.intent.md` を書く（書式は [intent-template.md](intent-template.md)）。

- **伝えたいこと**: 何を示す図か（示したい領域・量・関係・状況）を一文で。
- **対象と関係**: 曲線・直線・領域・立体・ベクトル・装置などの対象と、その厳密な関係（式、対称、平行・垂直、等長、角、接点、交点、比）。交点・頂点・切り口は式や幾何から**計算**して書く。
- **本質の印**: 斜線が表す領域、白丸（含まない）と黒丸（含む）、破線（補助か除外か）、矢印の意味、角の印・等長印、図題・注記。種類タグを付ける。
- **文字**: 図に書く文字を全部。薄くて小さくても意味のある印（小さな数字、目盛り）を含める。図の外に切れて写る本文は含めない。
- **読めない**: 判読できない文字は `[?]` とし、当て推量で描かない。仕様に残して図からは外す。
- **投影（立体）**: 投影（斜投影・等角など）を1つ選び、軸の向きと比、隠れ線の扱いを書く。

### 2. 仕様から正確に描く

1. 仕様どおりに、直線・円・式で定まる曲線で構成する。座標グラフは正方向の矢じり、軸名、原点 O。歪みは直す（揺れた線は直線や式の曲線に、崩れた対称・比率・寸法は仕様の関係に合わせて復元、立体は一貫した投影、隠れ線は破線）。色は原図から測り平塗りにする（`data-source-colors`）。
2. Python が使えるなら、文字は手で `<text>` を組まず [math_label.py](../scripts/math_label.py) で組む（使えなければ [conventions.md](conventions.md) の文字組みに従って書く）。和文・点名・数字は立体、変数は斜体、指数・添字を正しい高さに。書体で筆跡を模倣しない。
3. 原図にない要素（重力の分解、描いていない反射光線、図に無い数値、解答文だけにある辺長や面積）は足さない。
4. 重ね書きで判断が難しい箇所は、拡大や一時的な筆跡マスクを測定の補助に使える。[筆跡抽出ツール](../scripts/trace_strokes.py) の輪郭は交点や幅を測る下図に限る。

### 3. 検算して納品する

1. 仕様の式で描いた幾何を確かめる（半径、頂点、交点、角、等長）。SVG を掲載幅で描画し、原図と並べ、意図が伝わるか確かめる。
2. Python が使えるなら、SVG のルートに `data-mode="A"` を付けて `python3 "$S/lint_svg.py" --strict figure.svg` を回す（付けない場合は `--intent=figure.intent.md` を渡す。どちらも無いと仕様との照合は行われない）。`<title>`、`<desc>`、`role="img"`、寸法に加え、仕様と図の照合（仕様の文字と印が図にあるか、仕様にない文字を足していないか、`[?]` の候補を描いていないか）が出る。直す。Python が無ければ、仕様の「文字」「本質の印」を1件ずつ図と突き合わせる。

## Mode B　原図の配置を再現して照合する

元の作図データがあれば、その線・図形・文字を利用する。画像しかない場合は、左上を基準に各要素の座標、線幅、破線の間隔、字面と基線、色を測り、直線、円、滑らかな曲線と活字で組み直す。原図に色がある線は平塗りの同じ色で再現し、`data-source-colors` に書く。余白と縦横比を含めて原図の範囲を保つ。斜面の分力は元のパネル内に置き、スイッチは接点と刃の隙間まで確かめる。図題、キャプション、番号の書き方（空白やダッシュの種類を含む）、字間、ラベルの表記は原図を正確に写す。体裁をそろえるために詰めたり、書き換えたりしない。作図標準は、原図が決めていない事項にだけ用いる。標準と異なる表現に気づいたときは、標準へ寄せず、原図の状態を記録して再現する。

### 原寸での確認

SVG に title、desc、role="img"、data-mode="B" を付ける。原図は余白も含めて一度だけ切り出す。

**普段の確認**：SVG を原図と同じ寸法で描画し、原図と並べて（または重ねて）比べる。線の端点、接点、交点、記号、スイッチや極板の状態、文字の位置と表記を局所的に拡大して確かめ、ずれた箇所だけを直す。ほとんどの図はこれで足りる。

### 数値による採点（必要な案件だけ）

原図への忠実さを数値で示す必要があるとき（依頼で求められたとき、多段回路などで目視では判断しきれないとき）だけ、次の採点ループを使う。Chrome または Chromium、Pillow、NumPy、OpenCV が要る。使えない環境では上の普段の確認で納品し、数値採点をしていないことを伝える。

```sh
# S はスキルの scripts ディレクトリ。回ごとに新しい出力先を使う。
python3 "$S/lint_svg.py" --strict figure.svg
python3 "$S/fidelity_loop.py" --source source.png --svg figure.svg --out-dir iter-0
```

- Chrome は原図と同じ整数ピクセルの画面に、SVG を固有寸法、左上揃え、余白ゼロ、倍率 1 で描く。大きな SVG は画面外で切れ、小さな SVG の外は白になる。切り出しに合わせる修正は SVG 側で行う。原図と描画を白に合成し、両方の輝度が同じ `--cutoff` 以下の画素を前景とする。既定は 200。淡い塗りに 236 などを選んだ図は全試行でその値を使う。
- 両前景を Zhang–Suen 法で細線化する。並列削除で消える独立した点は、元の連結成分の重心に最も近い前景画素を1個残す。次に同じユークリッド円盤（`--dilate`、既定半径 2 px）で膨張する。`iou_norm` はこの二つの前景の積集合面積 ÷ 和集合面積。印刷の線太り、アンチエイリアスや書体の違いで影響を受ける生の画素 IoU に比べて線の位置を評価しやすい。**合格条件は文字を含む iou_norm ≥ 0.90**。
- `iou_raw` は細線化前の前景 IoU。`f1_1px` は相手の前景からユークリッド距離 1 px 以内に入る比率を双方向に測った調和平均。必要なら原図と同寸のマスクを `--text-mask labels.png` で渡す。白（輝度128以上）の文字枠を正規化後の両前景から除いた `iou_norm_notext` は、残った差が書体によるか調べる参考値である。
- `iou_norm_text` は同じ Chrome が測った文字枠（変換・添字を含む）の和集合に限り、正規化済みの積集合を和集合で割る参考値。該当する前景がなければ `null`。枠内の線も含み、SVG に存在しないラベルは自動計測できない。既定の `iou_norm_notext` はその枠外。`--text-mask` があるときは従来どおり指定マスクで文字除外値を測り、文字枠内の値は自動計測する。合否と打ち切りは全図の `iou_norm` で判定する。
- 文字の修正候補には元の文字列・文字枠・推奨入力・ヘルパーのコマンドがある。原図の添字や区切り記号を拡大して確かめ、上位1〜2領域だけを直す。
- `feedback.md` を読み、`overlay.png` の番号と上位の `regions/region-NN.png` を開く。クロップの左から原図・SVG描画・差分。橙は原図にだけある線（不足）、赤紫はSVGにだけある線（余分）、青緑は一致。番号は正規化後の残差画素数が多い順で、既定は上位12件（`--max-regions`）。`render.png` は原寸、`feedback.json` には同じ候補と換算情報がある。
- SVG の編集位置は `bbox_svg` の [左, 上, 幅, 高さ] を使う。`bbox_px` は描画像の画素単位。同寸・同じ縦横比なら、viewBox を [vx, vy, vw, vh] として `x = vx + px × vw / 画面幅`、`y = vy + py × vh / 画面高`。固有寸法や縦横比が異なる場合は `feedback.md` に出た図固有の式で換算する。SVGキャンバス外に編集座標はなく、境界をまたぐ矩形の `bbox_svg` は内側だけを示す。
- `shifted` は、その領域の SVG の線を整数画素だけ動かすと重なりが明確に増える場合。`offset_svg` は右・下を正とするユーザー単位の移動候補で、`null` は推定なし。古い読取ツール用の `score.json` の `bbox` は画素単位。`suggested_shift` は全体の診断値であり、SVGにも採点にも適用しない。

### 修正と終了判定

1. 初回は `iter-0` に採点し、同じ回の SVG を保存する。目標に達したら終了（終了コード 0）。未達（1）の場合は、**今回は上位1〜2件だけ**、クロップで確認できる端点、記号、字面などを直す。図全体の線を引き直さない。
2. しきい値・膨張半径・切り出しを固定し、修正版を新しい `iter-N` に保存して再採点する。後退したら最良 SVG に戻して、その版のフィードバックから別の直し方を選ぶ。後退した回も修正回数に含める。採点エラー（2）は原因を直してから判定する。
3. 最高値の更新が2回連続でなければ停滞で終了する。同点・後退は各1回と数え、どれだけ小さくても正の更新で連続回数をゼロに戻す。修正上限は初回を除く8回。

未達なら「0.90 未達」と記し、採用 SVG の `iou_norm`、`iou_raw`、`f1_1px`、終了理由と残差領域（矩形・不足／余分・内容）を示す。手描きの Mode A はこの採点の対象外であり、教科書図としての読みやすさ、元の印、lint で確認する。

多段回路や複合装置では全体の点数に加えて、小領域の重ね画像を原寸以上で見る。特に添字、極板、スイッチ、破線の再開位置を調べる。添字だけがずれる場合は親文字を動かさず、基線からの下げ量を調整する。淡い面があるときは、その内部と紙面を分離できるしきい値を初回に決め、原図と清書の両方に使う。色のある領域は明るさの照合と別に色見本でも確かめる。文字の縁だけに交互に現れる色にじみは、線の意味を表す色と区別する。
