# 目視確認の観点と典型的な失敗

PNG にした図を自分の目で見て，上から順に確かめる。1つでも当てはまれば直して，もう一度 PNG にする。

## レンダラーについて

- 確認は Chrome / Chromium のヘッドレス（`render_png.py` の既定）か `rsvg-convert` の結果で行う。
- cairosvg は `<tspan>` を含む文字列（斜体と立体を混ぜた式，添字・指数）の位置を崩して描くことがある。cairosvg の画像で文字がずれて見えても，SVG 側を直す前に別のレンダラーで確かめる。逆に，cairosvg でしか確認できなかった図は，文字の位置を未確認として伝える。
- 既定の 2 倍の解像度で足りないときは `--scale 3` で拡大して見る。

## 1. 正しさ（最優先）

- [ ] 交点・接点・垂線の足・中点が，線の上に正確に乗っている（黒丸が線からずれていない）
- [ ] 接線が曲線に接している（交差していない，離れていない）
- [ ] 直角の印がある角が直角に見える。印の無い角が直角・二等辺に見えない
- [ ] 問題文の条件（長さの比，角度，位置関係，大小）と図が一致している
- [ ] グラフの形が正しい（切片，極値，漸近線，増減，凹凸）
- [ ] 縦横の縮尺が意図どおり（円が円に見える，45° の線が 45° に見える）
- [ ] 縦横の縮尺を変えた図には，図の下の注記か y 軸の数値の目盛りがある
- [ ] 力の矢印の作用点・向きが正しい。すべての力が同じ尺度で描かれている
- [ ] **つり合う力どうしの長さを PNG 上で比べる**（垂直抗力と $mg\cos\theta$ の破線，摩擦力と $mg\sin\theta$ の破線，張力と重力）。見えている部分の長さが同じか。根元が物体や他の矢印に隠れて短く見えていないか
- [ ] 接触面に沿う力（摩擦力）が面の線と重なっていない
- [ ] 回路：電池の正負の向き，電流計は直列・電圧計は並列，分岐点の黒丸，つながるべき線がつながっている
- [ ] レンズ：光線が像の先端で1点に交わる。像の向き（倒立・正立）と大きさが計算と合う
- [ ] 磁場・電流・力の向きが法則どおり

## 2. 読みやすさ

- [ ] 文字が線・点・他の文字・ハッチと重なっていない
- [ ] 文字が図の端で切れていない（右端・下端の軸ラベル，長い式のラベル）
- [ ] どのラベルがどの点・線のものか迷わない（近くに別の点が無い）
- [ ] 文字の大きさが揃っていて，小さすぎない
- [ ] 変数はイタリック，点の名前・数字・関数名は立体になっている
- [ ] 添字・指数が正しい位置にあり，後ろの文字の基線が戻っている
- [ ] 分数が縦組みになっている（`5/6`，`π/2` の斜線分数が無い）。括線が前後の文字の中心の高さにある
- [ ] 座標のカンマの後に空白がある（`C(0, 0, 2)`）
- [ ] 質量 $m$ が物体の内側にある
- [ ] 負の符号が「−」，プライムが「′」で表示されている（□ や ? になっていない）
- [ ] 和文が表示されている（豆腐になっていない）

## 3. 体裁

- [ ] 線の太さが段階どおり（本体が補助線より太い，力の矢印が最も太い）
- [ ] 破線・一点鎖線が意図した線に付いている。破線の切れ目が潰れていない
- [ ] 矢じりが付くべき線に付き，向きが正しく，先が潰れたり線が突き出たりしていない
- [ ] 隠れるべき線が隠れている（物体の下の線，白丸の中の線，計器の円の中の線）
- [ ] ハッチが領域の内側だけにあり，境界線の上にはみ出していない
- [ ] 余白が均等で，図が片側に寄っていない。無駄に広い空白が無い
- [ ] 白黒だけで読める

## 4. 本文との一致

- [ ] 図の記号が本文（問題文・解答）の記号と同じ文字・同じ書体
- [ ] 本文で言及する点・線・角が図にある。図にだけある記号が無い
- [ ] 本文の数値を変えた後，図も作り直してある

## 典型的な失敗と直し方

| 症状 | 原因 | 直し方 |
|---|---|---|
| 点が線から少しずれている | 座標を手で丸めて書いた | 計算した値をそのまま変数で渡す |
| 接線が曲線を横切る | 傾きを目分量で決めた | `tangent_at` か導関数の式で傾きを出す |
| 一般の三角形が二等辺に見える | 頂点を左右対称に置いた | 頂点の x を中央からずらす（例 `A=(1.8, 3.6)`） |
| 円が楕円に見える | x と y の縮尺が違う | `yunit` を外す |
| 軸のラベルや長い式が右端で切れる | 窓・余白が足りない | 窓を広げるか `margin=(左, 右, 上, 下)` を増やす。ラベルを内側の向きに変える |
| 目盛りの数字に漸近線・曲線が重なる | 既定の向き（下・左）に線が通っている | `(値, ラベル, "SE")` のように向きを変える |
| 原点の O に曲線が重なる | 原点を通るグラフ | `axes(origin=None)` にして空いた象限に置く |
| ラベルが図形の内側に入り込む | `dir="auto"` が線を避けて内側を選んだ | `dir` を指定する |
| 2つの点が近くてラベルが紛らわしい | 点の間隔が狭い | 図の縮尺を上げる。ラベルを互いに反対側へ |
| 矢印の先が四角い | 線が矢じりの先まで届いている | 線を 5px 手前で止め `refX` を合わせる（`hsfig` の `arrow=` を使う） |
| 始点側の矢じりが逆向き | `auto-start-reverse` 非対応のレンダラー | 逆向きの marker を別に定義する |
| 文字が上下逆さま・鏡文字 | `transform="scale(1,-1)"` のグループに文字を入れた | 変換を使わず px 座標で書く |
| 添字の後の文字が下がったまま | `dy` を戻していない | 次の `<tspan>` に逆向きの `dy` |
| 式の文字が重なる・離れる（cairosvg だけ） | cairosvg の tspan の扱い | Chrome か rsvg-convert で確認する |
| 破線が実線に見える | 丸い線端で切れ目が埋まった | 破線に `stroke-linecap="butt"` |
| ハッチが領域の外に出る | 多角形の点の順序が交差している | 境界を一筆書きの順に並べる（`region_between` を使う） |
| 物体の下の線が透けている | 塗りが `none` | `fill="#fff"`（または薄い灰色）にし，描く順序を後にする |
| グラフの漸近線の所に縦線が出る | 途切れる関数を1本の折れ線にした | `plot` を使う（自動で分ける）。手書きなら区間を分ける |
| グラフがカクカクしている | 点が少ない | 200 点以上にする |
| 式の値が `5/6` と斜線の分数になっている | ラベルに `/` で書いた | `"$\\frac{5}{6}$"` にする |
| グラフが実際より大きく（急に）見えるのに断りが無い | `yunit` を変えたまま注記なし | `fig.note("※ 縦軸方向は拡大して描いてある")` か y 軸に数値の目盛り |
| 垂直抗力が分力 $mg\cos\theta$ より短く見える | 力ごとに長さを決めた／矢印の根元が物体の中で重力の矢印と重なっている | `set_force_scale` と `force_polar` で同じ尺度にする。作用点を重力の作用線と接触面の交点に取り，黒丸を打つ |
| 摩擦力の矢印が斜面の線に埋もれる | 接触面の線の真上に描いた | `shift=5` で物体側へずらす |
| 質量 $m$ が物体の外の角にある | 頂点を基準にラベルを置いた | `block(..., label="$m$", label_at=(…))` で内側に置く |
| 座標が `C(0,0,2)` と詰まっている | 手で `<text>` を書いた | カンマの後に空白を入れる（`hsfig` のラベルは自動で補う） |
| 回路の電池の向きが逆 | A, B の順と `plus_at_a` の取り違え | PNG で長い線の側を確かめ，引数を直す |
| 回路の素子の名前が配線と重なる | `side` が配線のある側 | `side=-1` にする |
| 力の矢印の名前が矢印に重なる | 既定の向き（矢印の延長上）に他の線がある | `dir` を指定する |
| 別の SVG と並べると矢じりやハッチが化ける | `id` の衝突 | 図ごとに `id` の接頭辞を変える（`Figure(..., id="fig2")`） |
| 暗い背景で線が見えない | 背景が透明 | 白い矩形を最初に置く |

## lint の指摘の読み方

- `ERROR 文字が viewBox の外にはみ出している`：必ず直す。
- `WARN 文字に線が重なっている`：文字の箱は概算なので，指摘された座標を PNG で見て判断する。白い下地つきで意図的に重ねたものは `data-lint="skip"` で外れる。
- `WARN 文字どうしが重なっている`：ほぼ確実に重なっているので直す。
- `WARN 斜線の分数がある`／`座標のカンマの後に空白が無い`：直す（単位の `m/s` などは対象外）。
- `WARN 線が viewBox の外に出ている`：窓の端で切れてよい線（窓いっぱいの直線など）でなければ，窓を広げる。
- 指摘が無くても，正しさ（1 の項目）は lint では分からない。必ず目で見る。
