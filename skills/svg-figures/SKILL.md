# svg-figures：高校数学・物理の図を SVG で描く

教科書や入試問題に載る図と同じ水準の，正確で読みやすい白黒の SVG を作る。図は答案や解説の一部なので，長さ・角度・交点の位置が式と合っていることが見た目より先に来る。

スクリプトはこの SKILL.md と同じフォルダの `scripts/` にある（以下 `$S`）。どれも Python 標準ライブラリだけで動く。

## 原則

1. **座標は必ず計算で決める。** 交点・接点・垂線の足・中点・外心・像の位置・極値を，目分量の数値で書かない。式を解くか `hsfig.py` の幾何関数で求め，その値をそのまま使う。計算で出せない位置（ラベルの置き場など）だけを手で決める。
2. **縮尺と縦横比を正しく。** グラフは x と y を同じ縮尺にするのが既定。図形は「30° の角が 30° に見える」こと。**縦横の縮尺を変えたら，必ず図の中で明示する**：図の下に小さく「※ 縦軸方向は拡大して描いてある」と注記する（`fig.note(...)`）か，y 軸に数値の目盛りを入れる。`<desc>` に書くだけでは足りない（読者には見えない）。どちらも無いと `save()` が警告する。
3. **力の矢印は1つの尺度で。** 1枚の図の力は，すべて同じ尺度（例：$mg$ を 1 として長さ 2.3）で長さを計算してから描く。つり合う力の矢印は，相手の力・分力と同じ長さになる。
4. **問題の条件と図を一致させる。** 条件に無い性質（二等辺に見える，直角に見える，接しているように見える）を図に持ち込まない。一般の三角形は，辺の長さも角もばらばらに取る。
5. **描いたら必ず画像にして見る。** SVG の文字列を読んでも重なりや崩れは分からない。PNG にして自分の目で確かめ，直す。最低1周。
6. **図中は記号と短い名称だけ。** 記号の説明（「⊙ は紙面の裏から表…」），凡例，式（$F=IBl$），状況の説明は図に書かず，本文のキャプションに書く。図の下の注記（`note`）は縮尺・模式図の断りを1文だけ。

## 手順

1. **何を見せる図か決める。** 主役（面積，接線，力のつり合いなど）を1つ決め，載せる要素とラベルを列挙する。解答本文で使う記号と同じ記号だけを載せる。
2. **数学座標で構成要素を計算する。** 窓（x, y の範囲）と縮尺（1 が何 px か）を決め，点・交点・接点などを計算する。
3. **SVG を生成する。** `hsfig.py` を使う Python スクリプトを書いて実行する（下の「ヘルパー」）。手で SVG を書く・直すときは `references/conventions.md` の骨組みと断片に従う。
4. **機械検査。**
   ```bash
   xmllint --noout fig.svg            # 整形式（無ければ lint_svg.py だけでよい）
   python3 $S/lint_svg.py fig.svg     # viewBox，外部参照，title/desc，文字の重なり・はみ出し
   python3 $S/lint_svg.py --display-width=650 fig.svg   # 表示幅（既定 650px）での文字・寸法の大きさを検査
   ```
   ERROR は必ず直す。WARN は該当箇所を PNG で見て判断する（文字の箱は概算）。
5. **PNG にして自分で見る。**
   ```bash
   python3 $S/render_png.py fig.svg   # fig.png を SVG の隣に作る（2倍の解像度）
   ```
   できた PNG を画像として開き，`references/qa-checklist.md` の観点で確認する。直したら 3〜5 を繰り返す。
6. **納品。** SVG 本体（必要なら PNG と生成スクリプトも）。条件から読み替えた点や，自信の無い箇所があれば一言添える。

### PNG 化に使うレンダラー

`render_png.py` は次の順に探す（`--renderer` で指定もできる）。

| 順 | レンダラー | 備考 |
|---|---|---|
| 1 | Chrome / Chromium のヘッドレス | 第一候補。ブラウザと同じ描画になる。macOS は `/Applications/Google Chrome.app`，Linux は `google-chrome` / `chromium` などを探す |
| 2 | `rsvg-convert`（librsvg） | 第二候補 |
| 3 | cairosvg | 簡易確認用。`<tspan>` を含む文字列（$M=\sin 1-5/6$ のように斜体と立体を混ぜた式，添字）の位置を崩して描くことがある。文字の位置はこの結果で判断しない |

Chrome を手で使うなら，SVG を `<img>` で読む HTML を作って撮る。

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new \
  --screenshot=out.png --window-size=W,H file.html
```

cairosvg しか無い環境では `uv run --with cairosvg python3 $S/render_png.py fig.svg`（または venv に入れる）。どれも無いときは `render_png.py` が導入方法を表示する。PNG にできなかった場合は，その旨を納品時に伝える（確認済みと書かない）。

## ヘルパー `scripts/hsfig.py`

数学座標（y 上向き）で図を組み立て，変換・外部参照・CSS を使わない素の SVG を書き出す。

```python
import sys; sys.path.insert(0, "<このスキルのフォルダ>/scripts")
import hsfig as hs
from hsfig import Figure

f = lambda x: x * x
g = lambda x: x + 2
x1 = hs.solve(lambda x: f(x) - g(x), -2, 0)        # 交点は方程式を解く
x2 = hs.solve(lambda x: f(x) - g(x), 0, 3)

fig = Figure(-2.6, 3.4, -1, 6.4, unit=40,          # 窓と縮尺（1 = 40px，x と y は同じ）
             title="放物線と直線で囲まれた部分", desc="…図の内容を1〜2文で…")
fig.hatch(hs.region_between(g, f, x1, x2))         # 面積は斜線
fig.axes(xticks=[(x1, "$-1$"), (x2, "$2$")])       # 軸，x・y・O，目盛り
fig.plot(f, -2.6, 3.4)                             # 400 分割で計算
fig.line_through((x1, g(x1)), (x2, g(x2)))
fig.label("$y=x^2$", (-2.3, f(-2.3)), dir="E", dist=8)
fig.save("parabola-area.svg")                      # ラベルの重なりは標準エラーに警告
```

主な機能（引数の詳細は各関数の docstring）。

| 種類 | 関数 |
|---|---|
| 幾何の計算 | `midpoint` `lerp`（内分・外分） `foot`（垂線の足） `reflect` `intersect_lines` `intersect_line_circle` `intersect_circles` `tangent_points` `circumcenter` `incenter` `inradius` `orthocenter` `centroid` `rotate` `polar` |
| 関数の計算 | `solve`（二分法） `deriv` `tangent_at` `region_between` `circle_region` |
| 線・図形 | `segment`（`arrow="end"/"both"/"mid"`） `arrow` `line_through`（窓いっぱいの直線） `polyline` `polygon` `circle` `ellipse` `arc` `smooth`（導線・糸など自由な形をなめらかに） |
| グラフ | `axes` `xaxis` `yaxis` `plot`（窓の上下で切り，漸近線をまたがない） `param` `interval`（数直線の区間） |
| 点・文字 | `dot`（`open=True` で白丸） `point` `label` `note`（図の下の注記） |
| 印 | `angle_mark`（弧の本数 `n`） `right_angle` `tick_marks`（等長） `parallel_marks` |
| 寸法・引き出し | `dimension`（`row=` 段，`axis=`，短い区間は矢じりが外向き） `dimension_chain`（連続する寸法） `leader`（引き出し線つきラベル） |
| 向きの矢じり | `segment(..., arrow="mid")` `polyline(..., arrow="mid")` `mid_arrow`（曲線の途中）。大きさは線幅に比例 |
| 塗り | `hatch`（`intersect=` `exclude=` で共通部分・差） |
| 空間 | `oblique`（斜投影 3D→2D）。見えない辺は `style="hidden"` |
| 力学 | `ground`（床・壁） `block`（`label="$m$"` は内側） `set_force_scale` `force_polar`（大きさと向き） `force`（`shift=` `dot=`） `components`（分解） `force_balance` `spring` `pulley` `field_mark`（⊗ ⊙） `field_grid`（並べる。`strength=` で密度を変える） |
| 回路（JIS） | `wire` `junction` `resistor`（`variable=True`） `capacitor`（`charges=("$+Q$", "$-Q$")`） `battery`（`polarity=True` で＋−） `inductor` `switch` `lamp` `ammeter` `voltmeter` `meter` `ac_source` |
| レンズ | `lens_image`（写像公式） `optical_axis` `lens`（凸・凹） `ray` |

線の種類は `style=` で選ぶ：`"main"`（1.5），`"aux"`（1.0），`"axis"`（1.0），`"force"`（2.2），`"heavy"`（2.2。軸に重なるグラフの線），`"dash"`／`"hidden"`（破線），`"bound"`（含まない境界線。太い破線），`"guide"`（座標を読む補助線。細い点線），`"chain"`（一点鎖線），`"dot"`（点線）。

ラベルは TeX 風の最小記法で書く（ギリシャ文字は `\\theta` `\\varphi` `\\omega` など。`\\phi` と `\\varphi` は同じ字形 φ になるので，本文も `\varphi` に統一する。角度は `"$60^\\circ$"` か `"60°"`。「˚」は使わない）。`"A"` は立体，`"$x$"` `"$mg$"` はイタリック，`"$x_1$"` `"$x^2$"` `"$\\theta$"` `"$\\sin x$"` `"$\\vec{a}$"` `"$\\sqrt{2}$"` `"$F'$"` が使える。分数は `"$\\frac{5}{6}$"` で縦組みになる（例 `"$M=\\sin 1-\\frac{5}{6}$"`，`"$\\frac{\\pi}{2}$"`）。`"$5/6$"` と書くと警告が出る。座標は `"C$(0, 0, 2)$"`（カンマの後の空白は自動で補う）。

ラベルの位置は `dir=` で決める。`"N"` `"NE"` … の8方位，角度（度），`(dx, dy)`，`"C"`（中央），`"auto"`。`"auto"` は線と他のラベルを避け，図の重心（`away=` で変更可）から離れる側に置く。置き場が無い・重なっているときは `save()` が警告を出すので，`dir` を指定し直すか窓を広げる。立体の頂点や，線が混み合う場所では最初から `dir` を指定する方が早い。

サンプルは `examples/`（`make_examples.py` で10枚を生成。境界線と補助線の描き分け・引き出し線は `region-boundary`，寸法線の段と短い区間は `lens-dimensions`，電池の＋−と極板の電荷は `circuit-polarity`，過程の向きは `cycle-direction`，磁場の強弱は `field-density`）。新しい図は，近い種類のサンプルを写して書き換えるのが早い。

## 体裁の規約（要点）

詳細と SVG 断片は `references/conventions.md`。

- **白黒印刷が前提。** 線は黒，背景は白の矩形。色は使わない（区別は線種・ハッチ・ラベルで付ける）。灰色のベタは物体の塗り程度にとどめ，面積は斜線。
- **線幅は段階を固定。** 本体 1.5，補助線・軸・寸法 1.0，ハッチ 0.6，力の矢印 2.2。1枚の図で勝手な太さを増やさない。
- **破線**は補助線・見えない辺・漸近線（`5 3`）。**一点鎖線**は光軸・対称軸。
- **意味の違う破線は描き分ける。** 領域の含まない境界線は本体と同じ太さの破線（`style="bound"`），座標を読むための補助線は細い点線（`style="guide"`）。境界線は境界である区間だけに引き，軸まで延ばす部分は補助線の線種に変える。
- **形は直線・円・計算した曲線で描く。** たるんだ導線・糸のような自由な形を折れ線で描かない（角が立ってゆがんで見える）。通過点を決めて `smooth` でなめらかに結ぶか，直線に単純化する。問題の図を写すときは，物体の形（小球は円，板は長方形）と構成要素を問題の図に合わせる。
- **矢じり**は `<marker>`。軸の先，ベクトル，力，光線の向き。線の先端が矢じりの先から覗かないよう，線を少し短くして矢じりの先を端点に合わせる（`hsfig` は自動）。矢じりの幅は線幅の4倍以上（`hsfig` は線幅から決める）。向きを示す矢じりを載せるために線を太くしない。
- **点**は黒丸（半径 2.6）。含まない端点・除外点は白丸。
- **文字。** 変数・量を表す文字（$x$, $y$, $a$, $\theta$, $m$, $g$, $R$）はイタリック。点の名前（A, B, P），原点 O，数字，関数名（sin, log），単位は立体。和文の説明文の中に出る量記号もイタリック。フォントは外部から読まず，欧文セリフ＋和文明朝のフォールバックを指定する。
- **文字の大きさ（数値基準）。** 教材に置いたときの表示で，**本文字（ラベル）16px 以上，最小の文字（添字・指数・注記）12px 以上**。`hsfig` の既定は本文字 16px・添字 12px・注記 12px で，`size=` で一部の文字だけ小さくしない。表示幅（指定がなければ 650px）より viewBox の幅 $W$ が広い図は縮んで表示されるので，font-size は「16 × $W$ ÷ 表示幅」以上（最小の文字は 12 × $W$ ÷ 表示幅 以上）が要る。まず `unit` を下げて $W$ を表示幅以下にする。`save()` と lint がこの基準で警告する。同じ教材の図は文字の大きさをそろえる。
- **詰め込まない。** 力の矢印は 36px 以上，寸法を付ける区間は 28px 以上，矢印が3本以上ある物体は一辺 60px 以上。足りなければ縮尺を上げるか図を分ける。文字が線・矢印に接するなら，図を大きくして離す。
- **ラベルの置き方。** 図形の外側（重心から離れる向き）。線・他のラベル・ハッチと重ねない。線の名前は線の端か中点付近の外側。どうしても線の上に置くときは白い下地（`bg=True`）。ラベルどうしは 2px 以上離す。力の矢印に物体の名前や他のラベルを横切らせない。
- **引き出し線（`leader`）は名前を指すためのもの。** 2本の曲線が近い場所の曲線名，混み合う場所の点の名前に使う。**他の線・補助線・斜線の領域を横切らせない**（曲線の外側＝領域と反対の側から引く。横切ると警告）。長さ・高さは引き出し線でなく寸法線で示す。角の名前は引き出し線でなく角の弧に付ける。
- **寸法線。** 図形の外に段を作ってまとめる（1段目は図形の最も外の線から 16px，段の間隔 20px。区間ごとの寸法は内側の段，全体の長さは外側の段）。区間の長さで扱いが決まる：文字と矢じりが入る長さなら内向きの両矢印，入らなければ矢じりを外向きにして文字を外へ（`dimension` が自動で選ぶ），**28px 未満は寸法を付けられない**ので，縮尺を上げるか，誇張して描いて「※ 模式図」と断るか，その部分の拡大図を別に描く（警告が出る）。連続する寸法は `dimension_chain`。
- **座標平面。** 軸の先に矢じり，$x$ は右端の下，$y$ は上端の左，原点 O は左下。目盛りは必要な値だけ。
- **分数は縦組み**（分子・括線・分母）。`5/6` のような斜線の分数は使わない。**座標はカンマの後を空ける**：C$(0, 0, 2)$。`C(0,0,2)` と詰めない。
- **角・長さの印。** 角は円弧（等しい角は同じ本数），直角は小さな正方形，等しい辺は同じ本数の短い線。
- **SVG の作り。** `viewBox` 必須，`width`/`height` は表示サイズ，`<title>` と `<desc>`，`role="img"`。外部フォント・画像・CSS・スクリプトなし。座標は小数第2位まで。

## 図の種類ごとの要点

数学は `references/math-figures.md`，物理は `references/physics-figures.md` に，描き方と短いコード例がある。

- **関数のグラフ・接線・面積・領域**：x, y 同じ縮尺。曲線は 200 点以上。交点・接点・極値は計算し，黒丸と座標を読む補助線（`guide`）を付ける。漸近線は破線。面積は斜線で，境界線はその上に描く。接点の近くなど斜線が細くつぶれる所は，図中の短い語（「接する」）か拡大図で補う。特定の値（$a=1.5$ など）で描いた概形は，その値をキャプションに書く。
- **量の値は軸の目盛りに書く。** $p_1$，$V_1$ のような量の記号を，グラフ上の点の名前のように点の横に置かない。点には A，B などの名前を付け，値は軸の目盛りに書く。問題のグラフを写すときは，軸の名前も問題どおりにする（「変位 $Y$」「時刻 $t$」）。
- **三角形・円**：頂点は名前付きの点。垂線の足・中点・外心・内心・接点は関数で求める。条件に無い特殊な形にしない。
- **ベクトル**：矢印は本体と同じ太さ。和・差は平行四辺形の補助線を破線で。$\vec{a}$ は `"$\\vec{a}$"`。
- **空間図形**：斜投影（奥行きは 45° 方向に 1/2）。見えない辺は破線。頂点のラベルは `dir` を指定。
- **数直線・ベン図**：区間の端は黒丸・白丸で含む・含まないを示す。ベン図は全体集合の長方形と円，該当部分を斜線。
- **力の図**：**つり合いの式・運動方程式に現れる力は，慣性力（遠心力）も含めて全部描く**。圧力による力は面の外側から面を押す向きに描く（`force(..., push=True)`）。物体（可動壁・ピストン）は斜線か灰色で塗り，液体は薄い灰色，気体は白にして見分ける。力は太い矢印を作用点から引く（重力は重心から，垂直抗力・摩擦力は接触面から）。手順は ①`set_force_scale` で尺度を決める → ②全部の力の大きさを同じ単位（$mg$ を 1 など）で計算する → ③`force_polar(作用点, 大きさ, 向き)` で描く → ④つり合いの図は `force_balance()` で和が 0 か確かめる。重力の分解は `components`。接触面に沿う力（摩擦力）は面の線と重ねず，物体側へ線幅の3〜4倍（`shift=5`）ずらす。質量 $m$ は物体の内側に置く（`block(..., label="$m$")`）。床・壁は線＋片側の斜線。
- **回路図**：新 JIS（JIS C 0617）。抵抗は長方形，電池は長い線が正極，コイルは半円の並び，電球は円に×。ギザギザの抵抗やループのコイルは使わない。配線は水平・垂直，分岐点に黒丸。**電流・起電力の向きや極板の電荷の符号を論じる図では，電源を図に含めて＋−を書き（`battery(..., polarity=True)`），極板に $+Q$，$-Q$ を書く（`capacitor(..., charges=...)`）。**
- **過程の向き（p-V 図などのサイクル）**：全過程を同じ太さで描き，各過程の中央に向きの矢じり（`arrow="mid"`，曲線は `mid_arrow`）。一部の過程だけ太くしない。**軸や補助線と重なる線分があるときは，全過程を `style="heavy"`（2.2）に上げ**，軸（1.0）と見分けが付くようにする（矢じりも線幅に合わせて大きくなる）。速度などの矢印が軸と重なるなら，軸から数 px ずらす。
- **向きを問う問題（電流・力・起電力・回転）**：問題の図に選択肢の矢印があれば，同じ視点の図（多くは横から見た図）を描き，「選択肢の矢印」と「求めた向き」を並べる。真上から見た図だけで済ませない。
- **2つの状況を1枚に重ねない。** 置き換え前後，衝突前後などは上下（左右）に分けた2枚にするか，重ねるなら実線と破線で分け，どちらがどの状況かを本文のキャプションに書く。
- **レンズ**：像の位置と大きさは写像公式で計算。光軸は一点鎖線，代表的な3本の光線，虚像側の延長は破線。
- **波形・v-t グラフ**：縦横の縮尺が違ってよい代わりに，軸の量と単位，読み取る値の数値の目盛りを入れる（記号だけの概形なら `Figure(..., aspect_ok=True)`）。
- **前提を図に入れる。** 向きを決めるのに使う場（磁場の ⊗・⊙ や矢印と $B$），速度，電荷の符号（＋），正の向きの矢印は，その図に描く。本文にしか無い前提で向きを論じない。
- **磁場**：紙面に垂直な向きは ⊗（表→裏）と ⊙（裏→表）。磁力線は向きの矢じりを途中に。場所で強さが変わる磁場は，印の密度を本当に変える（`field_grid(..., strength=lambda x: 1 / x)`）か，$B_1$，$B_2$ を位置に添える。

## 解答・解説と一緒に使うとき

解答・解説を作るスキル（high-school-math-answers，high-school-physics-answers）と併用する場合も，このスキル単独で使う場合も，次を守る。

- **本文と図のラベルを一致させる。** 本文で「点 H」「角 $\theta$」「$S$」と呼ぶものは，図でも同じ文字・同じ書体・同じ字形（φ は本文 `\varphi`，図 `\\varphi`）で載せる。図にだけ出てくる記号，本文にだけ出てくる記号を作らない。本文で定義した記号のうち図で位置が決まるもの（図形の名前，直線，点，座標軸，ベクトル，寸法，式に現れる量）と，問題文の丸囲みの記号（光線㋐など）は，それを説明する図に入れる。**議論の主変数になる角は必ず角の弧で示す。** 図を作り終えたら本文の記号と1つずつ照合する。
- **記号・用語は教科書の表記に合わせる。** 原点は O（オー），不等号は ≦ ≧，ベクトルは $\vec{a}$，角は ∠ABC，三角形は △ABC，座標は P$(a, b)$。高校の範囲にない記号を図に持ち込まない。
- **図は解答の根拠になる精度で。** 図から読み取れる位置関係（交点の順序，大小，接しているか）が，計算結果と食い違わないこと。本文の数値を直したら図も作り直す。
- **図番号を問題の図と衝突させない。** 問題に図1，図2 … があるときは，解答・解説の図は「解図1，解図2 …」と呼ぶ（番号の規約は解答スキル側にある）。SVG の `<title>` も同じ名前にする。
- **省いたものを書く。** 問題の図から省いた素子・部品は，キャプションに全部挙げる。本文で参照する端子・点の名前は省かない。
- **説明は図の外。** 図題・記号の説明・線種の区別は，図の直下の本文（キャプション）に書く。Markdown の画像の代替テキストは平文にする（`<`，`$`，`|` を入れない）。
